# Waveshare SIM7600X ↔ Banana Pi M4 Wiring & Bring-up

The SIM7600X provides both **4G LTE** and **GNSS (GPS/BeiDou/GLONASS/Galileo)**.
On this prototype it replaces the wired NEO-6M from the original BOM, and it hangs
off the Banana Pi M4 rather than the ESP32.

---

## Connection options

### USB (recommended, what the prototype uses)

Plug the SIM7600X USB port into the Banana Pi. The module enumerates as a
composite CDC device exposing several serial ports. Typical Linux mapping:

| Device | Purpose |
| :-- | :-- |
| `/dev/ttyUSB0` | Diagnostics |
| `/dev/ttyUSB1` | **NMEA** GNSS sentence stream |
| `/dev/ttyUSB2` | **AT** command port |
| `/dev/ttyUSB3` | PPP / modem data |

> Port ordering is **not guaranteed**. Confirm on your board:
> ```bash
> ls -l /dev/ttyUSB*
> dmesg | grep -i --line-buffered "ttyUSB\|option\|GSM"
> ```
> If the numbering differs, pass the right ones with
> `--at-port` / `--nmea-port` to `vision-ai/gps_sim7600x.py`.

### 40-pin UART (unverified alternative)

The current M4 Zero V2 was tested through USB only. The following original design mapping is unverified for this board revision; confirm the manufacturer pinout, voltage levels and power arrangement before using it:

| SIM7600X HAT pin | Banana Pi M4 40-pin | Function |
| :-- | :-- | :-- |
| TXD | Pin 10 (UART RX) | Module → Pi |
| RXD | Pin 8 (UART TX) | Pi → Module |
| GND | Pin 6 | Common ground |
| 5V  | Pin 2 / 4 (or a separate 5V ≥ 2A supply) | Power |

The UART then appears as `/dev/ttyS*` (e.g. `/dev/ttyS1`). In Armbian, free the
port first with `armbian-config` → *System* → *Hardware* (enable the UART,
disable the serial console on it), then reboot. Only the NMEA-less AT flow is
available this way — use `--mode at`.

> **Power:** GNSS + LTE transmit bursts can pull > 2 A at 5 V. Feed the module
> from its own regulated 5V supply, not the Pi's 40-pin rail, or the Pi will
> brown out during network attach.

## Antennas

- **GNSS active antenna** → the u.FL/SMA connector labelled **GNSS**. It must have
  clear sky view; indoor reception is often insufficient.
- **LTE antenna** → the connector labelled **MAIN** (add **AUX** for diversity).

Swapping these is the most common "no fix" cause.

---

## Bring-up commands

On the AT port (`/dev/ttyUSB2` by default), 115200 baud, e.g. with
`sudo minicom -D /dev/ttyUSB2 -b 115200` or `picocom`:

```
AT                 -> OK                 (module alive)
AT+CGPS=1          -> OK                 (power the GNSS engine)
AT+CGPSINFO        -> +CGPSINFO: 3113.343286,N,12121.234567,E,250420,081806.0,44.1,0.0,0.0
AT+CGPS=0          -> OK                 (power GNSS down)
```

No fix yet looks like:

```
AT+CGPSINFO        -> +CGPSINFO: ,,,,,,,,
```

### Firmware variants

Some SIM7600 firmware revisions use the newer GNSS command set. If `AT+CGPS`
returns `ERROR`, use:

```
AT+CGNSSPWR=1
AT+CGNSSINFO
```

`vision-ai/gps_sim7600x.py` tries `AT+CGPS=1` first and falls back to
`AT+CGNSSPWR=1` automatically.

```bash
cd vision-ai

```
